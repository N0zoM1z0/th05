# Exact acceptance

A maintained source unit is exact when its complete generated bytes and
original ordered relocation sites match the pinned target. Source presence
and semantic equivalence alone do not establish exactness.

Required evidence:

1. Target identity from `config/targets.toml` and the pinned toolchain.
2. Complete native boundaries and actual compiler OMF/MAP ownership, with the
   original 16-bit ABI and link context preserved.
3. Two fresh deterministic builds of the new or affected source unit.
4. Full raw-byte equality, including padding, plus original relocation order.
   Do not mask, sort, normalize or repair compared output.
5. A working oracle control. The normal replay supplies a compiled negative;
   functions in the same replay may share it. Do not add a separate negative
   compilation for every function by default.

No CPU behavior model, allocation-failure/null-pointer case, exhaustive input
sweep, fault injection or whole-game run is required for unit acceptance.
Use a focused semantic experiment only to resolve an actual recovery ambiguity.
A whole tooling test suite is relevant to tooling changes, not each recovered
function. Unchanged accepted evidence is reused after input identity checks.

Count only maintained semantic source: compiler-generated code must be C/C++,
and genuine original assembly is reviewed and reported separately. Copied
bytes/instruction transcriptions, assets, placeholders and padding get no
authored-source credit. Enumerate instruction NOPs at the native boundary
review; linker alignment/relaxation NOPs are compared padding with zero credit.

Keep instructions, compiler tables, initialized semantic DATA, padding, vendor
code and unknown ownership separate. A DATA unit covers its whole actual
initialized contribution; BSS and game assets receive no initialized-source
credit. Function scopes end at the next actual function public or contribution
end; skipped neighbors cannot be silently included.

Bounded units may use symbol-only external bindings. Their holes remain outside
compiler-owned bytes and earn no credit. Matching a bounded unit establishes
neither whole-program placement nor standalone linkage.

Decoded OP/MAINE bytes, packed files and whole executables are separate claims.
The authored denominator remains unreviewed, so no global percentage is claimed.
The supplied Japanese target is candidate-local-attested, not independently
proved pristine. Reference projects and Ghidra views supply evidence, not
transferred acceptance.

[Receipt format reference](reconstruction/ORACLE_FORMATS.md) covers special
DATA/ASM/retained-producer formats when needed. Existing accepted receipts and
the raw-byte/relocation gates remain valid under this narrower workflow.
