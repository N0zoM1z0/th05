# MAINE registration helper candidates

Accepted: `maine-registration-alphabet-a` (49 bytes),
`maine-registration-commit-b` (113 bytes), and `maine-registration-frame-a`
(40 bytes). Each has two fresh raw/ordered producers and its own rejected
semantic control. The shared full28-byte type and252-byte pool remain
unchanged; they define no storage in these CODE owners. The failed commit-a
receipt remains unchanged; only the second loop's real initializer order was
corrected in b.

These are independent natural C++ owners for original MAINE alphabet rendering
`[0xBCED,0xBD1E)` (49 bytes) and glyph commit/wait `[0xC16C,0xC1DD)`
(113 bytes). The whole original scopes contain no NOP, padding or CODE data.
Their literal ordered MZ fixups are `[41]` and `[54,15]`. Each complete body
fits one ordinary compiler LEDATA; no artificial prefix or relocation sorting
is proposed. The initial packets were source-only; the focused producer results
and the still-unaccepted commit correction are recorded below.

The alphabet body reuses maintained TH04
`src/maine/score/alphabet_cursor.inl`, preserving its standard typed register
locals and genuine Master far-Pascal call. TH05's keyboard starts at row21,
rather than TH04's row18. The local API is near Pascal `(int col,int row,int
attr)` with RET6. Master `gaiji_putca` is far Pascal with four word parameters,
physically `0000:121A`. The negative changes row21 to row22.

Commit/wait is recovered from original TH05 behavior, using the complete
`th05/regist.cpp` entity and existing canonical `MotionBase<SPPoint>` geometry.
The 28-byte record has real phase/glyph bytes, full motion12, target4,
angle/speed bytes, frame word and six genuine unused bytes. Nine records are
allocated, eight are processed. The gaiji member is an encoded byte with the
same full byte domain as the reference's one-byte gaiji enum. No record is
shortened and no padding is invented. Layout assertions cover every field and
the complete252-byte pool. The source only references foreign storage.

Commit/wait is a genuine near no-argument void function. It transitions cloud
entities, computes integer `iatan2(dy,dx)`, stores the quantized byte angle and
sets positive subpixel speed96. The second loop counts nonfree records before
calling the real registration frame helper, then tests that pre-frame count.
That ordering preserves the final extra frame. No CF/SI status protocol or
packed-point return is substituted. The speed96 to80 negative changes real
motion. Sound is far Pascal `E80:02E6`, atan2 far Pascal `0000:1A8C`, and
`registration_frame()` is a true foreign near void function at `BD1E`.

The new local headers establish real first-declaration segments and share the
full28-byte entity. Existing headers are unchanged. Both wrappers use the
standard optimized large-model GAME5/BINARYE producer, with their own named
segment in `GROUP_01`, original code frameA54 and original DATA frame1011.
Both symbol-only binders contain real external endpoints and addresses, without
helper bodies, copied state, table values or `.stack`. The complete game and
foreign registration animation are not claimed restored. Menu1034 and update758
remain parked.

## Focused producer results and commit correction

The alphabet owner passed the strict `maine-registration-alphabet-a` replay.
The separate commit/wait replay `maine-registration-commit-a` produced two
deterministic 113-byte functions with the correct literal relocation order
`[54,15]`, but failed raw comparison. Its receipt and both producer trees remain
preserved. No exact or authored claim follows from that failed parent.

Native inspection of both commit positives found one five-byte difference at
relative offsets 76 through 80. The original initializes the second loop's
integer index before its pool pointer; the candidate initialized the pointer
before the index. The other 108 bytes match, including the first loop. The
single recovered source correction changes only the second loop's comma
initializer from `(ball = glyphballs, i = 0)` to `(i = 0, ball = glyphballs)`.
Both assignments remain ordinary typed C++ with explicit sequencing. The
loop count, active-record domain, pre-frame count, callbacks and speed control
remain unchanged; no register, ABI, header or compiler-option change is made.

The old source and failed receipt are archived in the private
`.analysis/maine-registration-commit-sequencing/` proof packet. Its inverse-edit
check reconstructs the old source byte for byte and checks that every other
producer input is unchanged. The corrected source is frozen for one fresh
focused replay; its success has not yet been established. The meaningful
speed96 to80 control still belongs to this complete 113-byte owner, not to an
independently accepted subfunction.
