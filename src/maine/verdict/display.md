# Remaining small verdict display functions

The current accepted producer is the complete ten-function family described in
[full.md](full.md). It accepts all three functions below, including animation108
with its original nonmonotonic fixup order. The earlier independent
`maine-verdict-comments-a` and `maine-verdict-stage-scores-a` receipts remain
historical evidence for66/258 bytes and their own Y-coordinate mutations.
The following notes describe the original standalone boundary review.

Native review of the complete interval after the main verdict calculation
identifies three independent ordinary C++ candidates:

| Candidate | Original extent | Bytes | Original ordered MZ fixups |
| --- | --- | ---: | --- |
| `verdict_comments_put()` | D16F..D1B1 | 66 | 62,35 |
| `verdict_animate()` | D1B1..D21D | 108 | 36,29,12,104,97,87,67,60,53,46 |
| `verdict_stage_scores_put()` | D21D..D31F | 258 | 172,148,124,100,76,52,28 |

All three are parameterless near C++ cdecl functions returning through ordinary
RET. Their full extents decode completely, with no instruction NOPs, switch
tables, padding or accepted overlap. No CF result, custom register-return API,
asset or bitmap array is part of these candidates. Original code frame is0A54
and DS is1011. Each independent proposal compares its complete contribution,
including all original relocations in their actual order.

The commentary renderer tests the first byte of the real foreign text buffer,
then renders its two rows at relative coordinates(48,296) and(48,312). The typed
foreign array is `shiftjis_t near [2][30]`, at DS5087 with the second row at50A5.
Its unsigned color word is DS15E6; the coordinates remain DS15E2/15E8. This is
storage/API evidence, not a new DATA definition. The older reference symbol
spelling `byte_15187` is not a reliable load-address calculation for the pinned
original. Native memory operands establish these actual DS offsets.

The score display renders six stage labels and the final-score label, all
foreign semantic strings at DS16FB,1704,170D,1716,171F,1728 and1731. It then
passes the six full `resident->stage_score[]` entries and full `score_last`
through the newly accepted near Pascal Score8 far-reference formatter at C67F.
The complete128-byte resident and eight-byte score union are reused unchanged.
The natural loop advances its vertical coordinate by32. No explicit register
hint is added: this TH05-specific function has no independently demonstrated
natural donor qualifier to restore. Both the standalone and complete-family producers verify the actual allocation.

The animation uses the maintained TH04 natural verdict-animation donor with
the original TH05 page0/show0, main calculation,64-frame delay, commentary and
input/palette-out steps. Genuine standard `outportb` intrinsics select the PC-98
VRAM access/display pages through A6/A4. They do not implement a compiler body,
custom return convention or register-allocation template. All other boundaries
retain their actual far Pascal signatures: palette show/fades and page copy in
frame0, PI load/apply/put/free and input/frame waits in frameE80. The PI filename
at DS16F4 is the foreign null-terminated `ude.pi` object. Neither it nor any PI
image is defined or credited by this CODE owner.

The animation's relocation order has two non-monotonic runs. A real standalone
compiler may produce identical raw bytes with a different FIXUPP/LEDATA phase;
such a result must remain unaccepted. Raw equality is not a substitute for the
original ordered relocation stream. No artificial prefix, record rechunking,
masking or sorting is proposed to avoid this gate.

Each candidate has a separate symbol-only binder reserving only the genuine
foreign extents outside its entire compiled function. The initial standalone packet preserved the formatter/resident headers and

bodies and guarded first-declaration contexts.
