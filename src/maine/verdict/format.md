## Full types and observed behavior

The score parameter is a real far reference to the unchanged canonical
`score_lebcd_t` union from `src/main/hud/resident.hpp`. The complete object has
eight unsigned digit bytes and the original continues-used alias. It is not
replaced by a smaller field view or an integer-address parameter. The native
far argument occupies four bytes; with left/top words, cleanup is eight bytes.

The score formatter can render nine glyphs from eight stored bytes: a highest
stored byte of at least ten contributes its tens digit first, followed by the
eight remainder digits. Leading zeroes are blanked except the final digit.
The output buffer includes its real terminator. This differs from TH04's
fixed-resident score display, whose natural digit-walking algorithm is only a
donor, not an unchanged ABI.

The fraction helper deliberately computes `1000000 / total` before multiplying
by share, unless total equals share. It preserves the original truncation and
zero-total behavior. Addition/subtraction updates the real unsigned 32-bit skill
state. TH05 additionally caches one quarter of the selected stage-completion
fraction before formatting it; this behavior is absent from the TH04 donor.
The fixed-two-digit flag is a byte and is cleared after the second number.

Both graphical APIs retain genuine far Pascal interfaces. The real
`graph_gaiji_puts` at `0000:383C` receives left, top, step, a far character
pointer and a full unsigned color word, with RETF12. The real
`graph_putsa_fx` is `0E80:011A`, with left/top/color and a far Shift-JIS pointer,
RETF10. Calibration's `0E7F:0124` is not the original endpoint. All calls use
the dynamic original color word at DS:`15E4`, rather than the donor's literal14.

Actual DS is `1011`. Other real state is the subtract byte `15EA`, fixed-digit
byte `1613`, capture-quarter byte `507C`, skill dword `507E`, and cached quarter
dword `5082`. The four separate foreign string objects are the score unit
`点` at `1614`, decimal point `．` at `1617`, percent sign `％` at `161A`, and
another physical decimal point at `161D`. Their duplicated text is not
coalesced or defined as a new DATA owner. Local glyph bytes are semantic
codepoints in the real gaiji domain; they are not copied font bitmaps.
