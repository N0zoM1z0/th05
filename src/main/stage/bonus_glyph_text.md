# Bonus caption selector strings

`main-stage-bonus-glyph-text-data-a` accepts all19 initialized DATA bytes:
two fresh producers, complete OMF/MAP contributions, original raw bytes and
empty ordered fixups pass. Its EMPTY→NUL text-control mutation is rejected.
There is no padding, CODE, BSS or font bitmap credit.

This ordinary C++ DATA owner contains the complete `gpCLEAR_BONUS[9]` and
`gpCONGRATULATION[10]` objects at original MAIN `[2245E,22471)`, 19 bytes,
DS `209D:1A8E..1AA1`. The real first address is even. The second byte array
starts at `1A97`, and the complete pair ends at `1AA1`; these odd byte
boundaries require no invented padding or preceding object.

The preceding accepted 42-byte bonus pointer bank ends exactly at `2245E`.
The following accepted 719-byte readable bonus text bank starts at `22471`.
Thus both complete boundaries have independent neighboring evidence. There
are no padding bytes, pointer cells or original MZ relocation sites here.

The source preserves the exact existing `const char near` array types and
global names declared by the accepted bonus interface. It expresses CLEAR as
three named fragment selectors, one named empty glyph, four BONUS fragments
and NUL. CONGRATULATIONS uses nine consecutive named message fragments and
NUL. It does not reproduce the corresponding font pixels or an opaque byte
blob. No struct, constructor, alignment option or C-only model is needed.

Original normal/all-clear bonus calls independently push DS `1A8E`/`1A97`
and call the actual far `GAIJI_PUTSA` at `0000:1DBE`. Its native byte-load
loop stops at NUL and writes TRAM character-code words, proving text-selector
semantics rather than bitmap rows. Named message fragments are corroborated
by the reference gaiji font's row-major 16-pixel grid and converter metadata.
That candidate font remains private; its pixel identity and ownership are
not claimed by this unit.

The selector counts also fit the actual layout: eight CLEAR BONUS glyphs at
TRAM column 20 and nine congratulation glyphs at column 19 both center on
the playfield's X = 224. The source's data are encoded captions consumed by
the text API, distinct from the font bitmap asset that renders them.

The outside-only binder supplies actual MAIN frames and a DATA prefix ending
at `1A8E`. The compiler must emit the complete 19-byte DATA contribution;
the binder provides no caption bytes, internal hole, stack or instructions.
No accepted input or caller changes are part of this proposal, and no whole
executable linkage or caller CODE acceptance follows.

The candidate is uncompiled and unaccepted. Acceptance needs two fresh
producers, complete gapless compiler DATA and MAP scope, all raw bytes,
