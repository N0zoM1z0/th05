# Bullet notes

Bullets, pellets, Cheetos and lasers in TH05's MAIN.EXE. Most C++ here is
adapted from ReC98 (`th04/main/bullet/update.cpp`, `th05/main/bullet/*`);
spawning, the Cheeto and pellet blitters, dirty-tile invalidation and the
laser ray/hit-test helpers stay assembly (see `spawn.md`, `cheeto_put.md`,
`gather_invalidate.md` and `laser_render_hit.md`).

## Code generation

- **`-G` and `register` in the renderers.** Without `-G`, `cheetos_render()`
  and `bullets_render()` compile with ENTER, two bytes shorter than the
  original PUSH BP / MOV BP,SP / SUB SP prologue, and with their register
  locals swapped. `-G` restores the prologue; marking the Cheeto node index,
  and the bullet renderer's pattern number and bullet pointer, as `register`
  restores the original allocation.
- **The sprite enum must keep its full word range.** `main_patnum_t` in
  `update.hpp` runs up to `PAT_MAX = 320`. Cutting it down to the constants
  used here makes it a byte enum, and the decay-pattern ternary in
  `bullets_update()` then compiles to AL/AH instead of AX operations.
- **`PlayfieldMotion::update_seg3()` returns a `PlayfieldPoint`** in DX:AX.
  The callers read `_AX`/`_DX` directly after the call, so it must not be
  declared `void`.
- **Same-segment far calls.** `sparks_add_random()` is a far call within
  main_03; TLINK relaxes it to NOP, PUSH CS, near CALL. That NOP is linker
  padding, not code.
- **Popup callback segment.** `bullets_update()` stores the near address of
  `overlay_popup_update_and_render()`, which lives in main_01 even though the
  updater is in main_03. Its first declaration has to be in main_01's
  context, or the stored offset is relative to the wrong group.
- **`bullet_update_special()`'s jump table** is generated by the compiler from
  the plain `switch`.
- `bullet_patnum_for_angle()` returns `unsigned char`, but computes a 16-bit
  value in AX and every caller uses all 16 bits; the narrow type is ZUN's.

## Data layout

- `bullet_t` is 32 bytes. The pool holds 400 bullets: 180 pellets, then 220
  16x16 bullets. Both loops iterate it backwards, so the 16x16 bullets come
  first.
- The Cheeto template is a 25-byte view of custom entity slot 0, a 26-byte
  slot; the seven heads are slots 1-7. Don't add a field to make the sizes
  agree. `cheeto_trails[]` has eight elements although only seven are used.
- `bullets_add_by_mode[]` (`add_dispatch_table.cpp`) holds the regular,
  fixed-speed and special spawners, in that order; the enemy script's bullet
  command calls through it.
- `bullet_zap_drop_point_items` must be compiled as C (`zap_drop_point_items.c`).

## Game behavior

- ZUN quirk: `bullet_template_clip()` sets `player_is_hit` for a bullet
  spawned on top of the player but still spawns it.
- ZUN quirk: the zap code uses TH04's sprite number for the zap animation, so
  the zap's decay animation never plays in TH05 (see `update.cpp`).
- ZUN landmine: fixed lasers wider than 127 pixels skip their shrink
  animation; see `laser.hpp`.
